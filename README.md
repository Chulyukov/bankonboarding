# Bankonboarding Shop API

REST API-сервис для управления товарами и расчета стоимости заказов (`OrderedInfoResponse`).

## 🛠 Стек технологий

* Java 21
* Spring Boot 4.1.1 (Web, Data MongoDB)
* MongoDB 7.0
* Docker & Docker Compose
* Lombok

## ⚙️ Требования

Для любого варианта запуска на вашем ПК должен быть установлен и запущен **Docker Desktop**, так как база данных всегда разворачивается в контейнере.

## 🚀 Быстрый старт

### 1. Настройка окружения

В корне проекта создайте файл `.env` на основе примера:

```bash
cp .env.example .env
```

Укажите в `.env` ваши локальные доступы (база данных, API ключи Dadata и т.д.).

### 2. Запуск проекта

Проект поддерживает два сценария работы: для локальной разработки и для полноценного развертывания.

#### Вариант А: Локальный запуск (через IntelliJ IDEA)

Оптимальный вариант для написания кода. Приложение запускается на хостовой машине, а база данных автоматически поднимается в Docker. Чтобы приложение успешно стартовало, ему необходимо передать переменные окружения.

1. Убедитесь, что Docker Desktop запущен.
2. В IntelliJ IDEA перейдите в настройки запуска: нажмите `Run` -> `Edit Configurations...`.
3. Выберите конфигурацию запуска `BankonboardingApplication`.
4. Подключите переменные окружения одним из способов:
* **Способ 1 (Рекомендуемый):** Установите плагин **EnvFile** в IDEA. В окне конфигурации появится вкладка `EnvFile`. Отметьте чекбокс *Enable EnvFile*, нажмите `+` и выберите ваш созданный файл `.env`.
* **Способ 2 (Ручной):** В поле `Environment variables` вручную скопируйте и вставьте все ключи и значения из вашего `.env` файла.


5. Нажмите кнопку `Run`.

> **Как это работает:** Благодаря модулю `spring-boot-docker-compose`, Spring Boot при старте сам прочитает файл `compose-db.yaml`, поднимет контейнер с MongoDB и автоматически настроит подключение к нему.

#### Вариант Б: Полный запуск через Docker Compose

Запуск и самого Spring-приложения, и базы данных в изолированной Docker-среде. В этом случае переменные из `.env` подтянутся автоматически.

1. Откройте терминал в корне проекта.
2. Выполните команду сборки и запуска:

```bash
docker compose up -d --build
```

> **Важно:** При сборке контейнера приложения Gradle сначала прогоняет `test`, а затем собирает `bootJar`. Это гарантирует, что микросервис не стартует без валидного набора тестов. Дополнительно в конфигурации для сервиса `app` прописано `SPRING_DOCKER_COMPOSE_ENABLED=false`. Это предотвращает конфликт, запрещая Spring Boot пытаться запустить вложенный Docker (базу из `compose-db.yaml`), когда приложение уже само находится внутри контейнера.
