Блок заданий №1. Тренировка в создании методов контроллеров, сервисов, обработка исключений
1.1) Сделать метод GET /welcome который отдает http code 200 c json объектом { "message": "Добро пожаловать в наш чудесный магазин" }
1.2) Сделать метод GET /product который отдает массив подготовленных продуктов со следующей информацией: идентификатор товара, название, цена за единицу
1.3) Сделать метод POST /calc - метод принимает массив объектов (идентификатор товара, количество) и отдает объект с итоговой суммой и массивом товаров (название товара, цена за единицу, количество, сумма). Если во входных значениях есть идентификатор с несуществующим товаром, то необходимо выдать ошибку http code 400 с объектом содержащим информацию о несуществующем товаре. Здесь необходимо воспользоваться Исключениями и ExceptionHandler

Блок заданий №2. Работа с базой данных, работа с Scheduling
2.1) Необходимо в проект добавить стартеры для работы с spring data jpa + mongodb. Добавить в конфиги приложения креды для подключения к бд. Убедиться, что приложение стартует (при старте происходит подключение к бд). Для локальной работы с бд настроить подключение к NoSQLBooster
2.2) В mongodb создать коллекцию products. Перенести данные продуктов в БД (тот что из задания 1.2), в сервисе добавить необходимый Entity и Repository, переделать методы GET /product и POST /calc на получение данных из БД.
2.3) Добавить в entity Product флаг "В наличии". Внести изменения, чтобы данный флаг влиял на отображение списка продуктов и на калькулятор.
2.4) Учимся работать с Scheduling Tasks. Необходимо, чтобы каждую минуту у нескольких случайных товаров менялся флаг "В наличии" на отрицательный. Остальные товары должны быть доступны. Каждое изменение должно логироваться с уровнем info.
2.5) Добавить в mongodb коллекцию discounts. В ней должны быть следующие данные: идентификатор скидки, название скидки, массив товаров для которых применяется скидки, размер скидки в процентах, признак включения, дата добавления скидки
2.6) Изменить поведение метода POST /calc чтобы он учитывал скидки. Скидки должны суммироваться, но не превышать 50%.

Блок заданий №3. Отдельные микро-задачки на разные темы
3.1 - 3.2) Необходимо покрыть код тестами. Основные методы покрываем unit-тестами. Интеграционные тесты используем для: проверки кодов и тела ответа контроллеров для позитивных и негативных сценариев; проверяем работу репозиторного слоя (используем тест-контейнер для монги); проверяем работу шедуллера.
3.3) Доработка метода POST /calc. В модель реквеста добавляется поле deliveryAddress. Добавляется внешняя интеграция через FeignClient до метода dadata api https://suggestions.dadata.ru/suggestions/api/4_1/rs/suggest/address (см документацию https://dadata.ru/api/suggest/address/). Обработка: полученный deliveryAddress отправляется в метод дадаты, получаем список совпадений, ищем первый объект с параметром [].data.fias_level = 9. Если объект с таким значением найден, то считаем, что адрес введен верно и продолжаем основной позитивный сценарий. Если такого объекта нет, то должны выбросить ошибку, что адрес доставки не найден. Для тестирования используем wiremock (интеграционный тест).
3.4) Задание на AOP. Добавить в ваш микросервис новую аннотацию @Log, которая ставится на методы. Через AOP сделать логгирование входящих данных в метод и возвращаемое значение метода.
